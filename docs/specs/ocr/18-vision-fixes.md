**Сквош** везде в этой спеке — `"".join(tokens)` у списка токенов (внутри токенов пробелов нет) и `"".join(s.split())`

#### `hints(rows)` — новый порядок

1. **`_raw_hints(rows)`** — как `hints` в #91 (строки `wrong_fix`, `kept` / `f` / `fs` / `fe`, опкоды
   `SequenceMatcher(None, f, W, autojunk=False)`, кроме `equal`, касающиеся пролёта и не `is_cosmetic`, пролёт в
   plain-токенах). У каждой сырой подсказки, кроме полей `Hint`:
   - `ours = f[i1:i2]`, `read = W[j1:j2]` — стороны опкода; у вставки `ours == []`;
   - `sources` — список окон, давших эту подсказку: `(row, f, W, kept, lo, opcodes)`.

   Повторы по `(start, end, suggestion)` схлопываются, как в #91: остаются поля первой, `sources` дописываются.
2. **`_merge(raw)`** — решение 3. Страница за страницей:
   - **Компонента** — подсказки страницы, чьи пролёты пересекаются: у отсортированных по `(start, end)` подсказок
     следующая входит в текущую компоненту, если `start < max(end)` компоненты. Касание без общего токена — не
     пересечение. Подсказки разных страниц не сливаются никогда.
   - Одна подсказка в компоненте — остаётся как есть.
   - Несколько: объединённый пролёт `[U1, U2)`. **Кандидат** — каждое окно из `sources` всех подсказок компоненты,
     которое:
     - накрывает пролёт: `lo <= U1` и `U2 <= hi`, где `hi = lo + len(row["fragment"].split())`;
     - оба края — живые токены: `U1 - lo` и `U2 - 1 - lo` есть в `kept`.

     Для кандидата: `p1 = kept.index(U1 - lo)`, `p2 = kept.index(U2 - 1 - lo) + 1`. Концы в `W` — по опкодам этого
     окна, как `to_b`:
     - `js` — опкод, где `i1 <= p1 < i2`: у `equal` это `j1 + (p1 - i1)`, иначе `j1`;
     - `je` — опкод, где `i1 <= p2 - 1 < i2`: у `equal` это `j1 + (p2 - 1 - i1) + 1`, иначе `j2`.

     Слитая подсказка: `start=U1`, `end=U2`, `suggestion=" ".join(W[js:je])`, `page` — страница, `reading` —
     `row["reading"]` кандидата, `ours=f[p1:p2]`, `read=W[js:je]`.
   - Кандидат, чья слитая подсказка обрезана (`_truncated`, п. 3), **не годится**.
   - Из годных берётся тот, у кого `|(U1 + U2) / 2 − (lo + hi) / 2|` меньше; при равенстве — первый (по порядку
     подсказок, потом `sources`).
   - **Годных нет** — «слить нельзя»: остаётся одна подсказка компоненты, у которой
     `|(start + end) / 2 − (lo + hi) / 2|` меньше. `lo, hi` — её первого окна из `sources`; при равенстве — первая.
3. **`_truncated(hint)`** — решение 2: `True`, если сквош `read` пуст **или** `ours` не пуст и сквош `read` —
   строгая подстрока сквоша `ours` (входит в него и не равен). Такие подсказки выбрасываются **после** слияния
   (решение 8).
4. **`_kind(hint)`**: `"chars"`, если `ours` пуст (вставка). Иначе `"space"`, когда сквош `ours` равен сквошу
   `read`, и `"chars"` в остальных случаях.
5. Возврат — `Hint(start, end, suggestion, page, reading, kind)`, отсортированные по `(start, end)`.

Внутреннее представление сырой подсказки (dict или приватный dataclass) — на усмотрение исполнителя, наружу
выходит только `Hint`.

#### `limit_pages(found)` → `(kept, flooded)`

- `flooded = {page: n}`, где `n` — число подсказок `kind == "chars"` на странице и `n > PAGE_HINT_LIMIT`.
- Подсказки `"space"` не считаются никогда.
- Страница из `flooded` гасится **целиком**, `"space"` тоже, как в #91: сбой нарезки портит и их.
- `kept` — остальные подсказки, в прежнем порядке.

Текст находки `vision_skipped` у затопленной страницы:
`стр. {p}: подсказок вида «буквы» {n} — больше {PAGE_HINT_LIMIT}, похоже на сбой нарезки или скана; подсказки
страницы не выданы, сверить страницу глазами`.

#### Колонтитул на стыке — решение 4

`ocr/measure.py` заморожен, а склейку «низ N + верх N+1» строит `run_measure`. Поэтому окна стыка **пересуживаются
в `ocr/vision.py`** после `run_measure`:

- `_Progress.transcribe` после успешного вызова кладёт ответ в `self.answers[self._keys[k]] = texts`, где `k` —
  номер вызова. Ключ — `(fixture, page)` из `page_tiles`.
- **`_footers(content_list, page)`** → множество сквошей `text` блоков с `page_idx == page - 1` и `type` из
  `("footer", "page_number")`. Пустой текст не берётся.
- **`_strip_footer(text, feet, tail)`** — строки `text` по `"\n"`. С края, с конца при `tail=True` или с начала
  при `tail=False`, выбрасываются подряд строки, у которых сквош пуст, или
  `_FOOTER_RE.fullmatch(сквош)`, или сквош ∈ `feet`. На первой другой строке — стоп. Середина текста не трогается.
- **`_rejudge_seams(cases, rows, answers, content_list)`**. `cases` и `rows` идут в одном порядке (так их отдаёт
  `run_measure`). Для каждого случая с `next_tiles`, у которого в `answers` есть обе страницы `k1 = ("", page)`
  и `k2 = ("", page + 1)`:
  - индексы — как в `run_measure`: `pt = page_tiles(cases)`, `last = pt[k1].index(case.tiles[-1])`,
    `first = pt[k2].index(case.next_tiles[0])`;
  - `row.update(judge(case, _strip_footer(answers[k1][last], _footers(cl, page), True) + "\n" +
    _strip_footer(answers[k2][first], _footers(cl, page + 1), False)))`.

  `crop`, `crop_next`, `cache_hit` не меняются. Окна не на стыке не пересуживаются.
- `vision_findings`, шаг 7 спеки 16, становится таким:
  `rows = run_measure(...)["cases"]` → `_rejudge_seams(cases, rows, wrapper.answers, content_list)` →
  `found, flooded = limit_pages(hints(rows))`. Счётчики `unreadable` / `clipped` покрытия считаются по `rows`
  после пересуда.
- `vision_diff`: `Finding(..., kind=hint.kind)`. Прочие поля — как в #91.
